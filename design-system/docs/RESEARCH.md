# Decision research — 4 November 2026

This research supports the next implementation slice, not a broad vendor survey. Primary sources were checked on 4 November 2026. Product choices below are design inferences, not claims that the source prescribes Kitty's architecture. No real household financial records were accessed for this work.

| Source | Verified observation | Decision for Kitty | Limit |

## Choices, alternatives and trigger to revisit

| Choice | Simpler alternative considered | Why this choice now | Revisit when |
|---|---|---|---|
| Adapt the existing vanilla components and Sheet model | New React app + database + chart/layout libraries | A rewrite introduces two data owners and a deployment problem before proving value. Existing architecture can support the next slice. | Measured complexity/performance or multi-user consistency cannot be solved within current boundaries. |
| Strict staging contract beside the existing template | Add dozens of live Sheet tabs now | Sidecar provenance closes an immediate trust gap without a migration or breaking the existing oracle. | A new domain has validated source adapters and a reviewed template migration. |
| Optional module invitation | Automatically add/reorder widgets on import | Data recognition is not user preference or proof a domain is ready. An invitation keeps the canvas predictable. | User testing establishes explicit opt-in rules for automation. |
| Evidence readiness first | Tax, CGT and SMSF calculators at once | Records, ownership, dates and reconciliation are shared needs; tax methods have distinct assumptions and acceptance requirements. | Versioned domain calculation methods, independent oracles and specialist review exist. |
| Exact decimal/integers at new boundaries | Continue floating point everywhere | Financial imports need deterministic precision; old Sheet formulas remain unchanged until separately migrated. | Never silently relax precision. Add currency-specific scale and rounding policies when supporting more currencies. |

## Remaining uncertainty

No current provider portal/download shape was independently verified. Existing adapters and new portal fixtures are synthetic test contracts. Real-bank compatibility needs samples with permission, documented version changes, safe account mapping and reconciliation. No new tax formulas are validated. No human usability study establishes that the chosen dashboard or mascot improves financial outcomes. The useful next evidence is completion of a bounded import/review/source-drill journey with a person and independent expected results, not a larger feature count.
