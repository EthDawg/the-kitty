# Decisions: the page from nothing

Taken on 7 November 2026 while building, without stopping to ask. Each is a default that can be changed. A stranger with one bank file reaches their own Home on the same app the demo uses.

## One engine

**The adapter writes a snapshot and `E.model` reads it.** `modelFromStandard` is `E.model(snapshotFromStandard(L, view))`. The shape the page reads has one builder, and the first-seen, duplicate, merchant and decision logic stays in one place. It takes the page's own engine, so the merchant dictionary and the money format are one.

**The adapter does no arithmetic of its own on money.** Cents become dollars, rows are filed under the page's names, and stated rows are added up within a group. What the standard does not state is blank and named in `UNSTATED` with the reason: goal pace, subscriptions, savings ideas, compliance checks, budget pace, mortgage scenarios, three-month savings rate, safety net. A household's page says "not worked out yet" or leaves the card off.

**Money in nobody can explain is its own category in the page's model.** The ledger keeps it out of income and spending until a person says. `UNPLACED` has the flow Transfer so `E.spend` agrees. It sits in the review queue, so it isn't hidden.

**A household's review queue is the standard's.** `E.review` asks sheet-era questions and flagged 391 lines on the world. `m.reviewQueue` is what the standard could not place, and the demo has none, so it keeps `E.review`.

## Parity

`src/household/PARITY.md`, regenerated by `node tools/page-parity.js --write`. Fields come from the source: a top-level read is `m.x`, a row field is a key of a v2 row that a `.key` reads. A browser test wraps the real model in a recorder and fails on a read the scan missed.

**Same accounts, same window.** The world is wider than the sheet on purpose, so the cash and net worth lenses run over the 18 accounts the sheet holds, from July 2025. The table says what was left out.

**It can't be made to pass by weakening it.** A differing field needs a written reason, no field may match fewer rows than `parity-baseline.json`, and the money itself is held to zero differences: every transaction's date, account, amount, description and flow, every month's income, spending and net, cash, property, super, loans, goals and payslips.

**`src/engine.js` is not retired and the demo stays on v2.** The adapter can read Davies. It can't yet state what the sheet computes.

## Two doors

**The door is the first screen for a first visit, and it replaces the old tour.** "See the Davies" goes straight to the demo. A tour asking a stranger's name over someone else's money was friction F017. It is still there under Setup, Run the setup again, and at `?onb`.

**`?noonb` skips the door,** as it skipped the tour, so every existing test and screenshot runs as it did. An owner's view, a viewer with a saved sheet and a returning viewer never see it.

**A page with no bundled data opens on Start yours,** unless a sheet is already saved. Before, an owner's blank copy read the public demo sheet.

**A viewer who has started never sees the demo first.** Boot checks the prefs before anything draws. The door goes up before the demo's first paint, so its confetti and toast don't play behind it.

## Start yours

**Three questions: your name, anyone else, where it lives.** Grown-up or child is the only thing asked about another person. The household is called "Name's household".

**Device mode is the Fake store in the page, kept in IndexedDB.** It is the same code as a Sheet, so moving across is a table-by-table copy into a new store. It says "On this device, not saved to your Sheet yet" wherever it matters. If the browser won't keep it, it says that too. The bytes of files no store holds are kept there too, so "on this device" stays true and a recipe can be applied after a reload.

**Drive is found by asking.** The page calls `search_files` once. A refusal means bytes are marked on device. It offers "make one for me" only when Drive answers.

**A sheet with anything in it is refused by name,** and a sheet that is already a Kitty opens as that Kitty.

## A file

**Three tries, in this order, on the coordinator's instruction.** The page's own reading of the columns, `src/household/guess.js`, runs by itself. If it fails or the person says no, the host's `sample` object writes a recipe, on a click, because that sends rows to Claude. Then the copy-to-agent prompt, with a paste box. All three go through the existing gate. All three show three rows before anything is saved. It is in the runtime, so `node tools/kitty.js guess file.csv` does the same.

**A no-header table is read by its contents.** The variant family's bank has no header row, so roles come from what is in the columns, and every way of reading the number columns goes to the gate.

**A file with no running balance proves nothing about its sign.** The gate passes it. `proposeRecipe` calls that `unproved` and the page asks the person to look. Dates that could be read either way are flagged, with the other reading one click away.

**Account names reuse.** A name a person already uses is that account, not a new one.

## Blank at every size

**Home is the same canvas with a household's parts.** A part with nothing true to say is null. Insights, Goals and Records have their own household drawing, which leaves the demo's code byte-identical. The arrangement is saved separately from the demo's.

**No savings rate, safety net or goal pace,** because the engine doesn't state them yet. The months card only appears at two months, and says how many.

**Next-step wording.** A transfer whose other side is an account we haven't met now says so, instead of "Two sides of the same money have not met: transfer". A payslip newer than the last bank line is a file still to come, not a question, and an unpaired transfer no longer stands in front of a close. Each would otherwise have stopped a first close.

## Build

**The runtime sits in the page as gzip in base64, inert, in a `text/plain` script.** "Start yours" inflates it with `DecompressionStream` and runs it as an inline script. One file to publish, no new host permission, and no parsing on the demo. If a host refuses, the page says so.

| Demo page | Before | After |
|---|---|---|
| `dist/kitty-v2.html` | 1,569 KB | 1,920 KB |
| First contentful paint, median of 7, twice, local server | 40 and 40 ms | 40 and 40 ms |
| DOMContentLoaded | 120 and 121 ms | 126 and 126 ms |

Activity, Insights, Goals and Records read exactly the same text before and after. Home adds one "Start yours" link. Setup changed as asked.

**`build.py` needs node for the household path.** Without it the page is built with no Start yours path and says so. The native build never carries it.

**The public page is `python3 build.py --v2`, `dist/kitty-v2.html`.** It needs the capabilities in README.

## Not proved

- **Nothing here has met the real connector.** The Sheets and Drive shapes are the runtime's guesses, and `update_spreadsheet` is not on the published page's declared list until it is republished.
- **Whether a host's content rules allow an injected inline script.** Inline scripts run in an artifact, so it should. The page says so plainly if not.
- **Google's pacing.** A page refresh is about 40 reads, and a drop adds more.
- **Whether a free Claude plan has connectors.** The page says it depends on the plan and points there.
- **A HELP page is read, and no HELP account comes of it.** `materialise` makes bank, card, loan and super accounts. "Not asked yet" still lists it. A finding for the runtime.
- **Split, merge and match** are hidden on a household's page. Their decisions exist, and the page has no proof of what the engine does with them.
- **Ask** works on the same model and has not been read through for a household.
- **The engine is experimental.** A fifth blind family was 14 of 63 silently wrong, and the page says so.
