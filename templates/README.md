# Clean household template generator

`build.mjs` creates a deterministic, reviewable plan for a new AU/AUD household workbook. It validates setup inputs and emits standard Google Sheets requests. It makes **no provider calls** and does not claim formula recalculation, ownership, private sharing or successful setup. Applying the plan and verifying a newly owned workbook belong to the bootstrap service.

```js
import { buildTemplate } from './templates/build.mjs';
const plan = buildTemplate(input);
// Review plan.reviewSummary and bind approval to plan.inputSha256.
// Only an authenticated bootstrap writer may apply and verify the requests.
```

```sh
node --test templates/build.test.mjs
node templates/build.mjs templates/example-input.json /tmp/kitty-example-plan.json
```

The CLI requires an explicit output filename, creates it with mode `0600` and refuses to overwrite an existing file. The example contains fictional input. A real setup plan contains household data and must not be committed or published.

## Input contract

```json
{
  "profile": "au-aud-basic",
  "sheetVersion": 1,
  "country": "AU",
  "currency": "AUD",
  "householdName": "River household",
  "people": ["Sam"],
  "openingDate": "2026-06-30",
  "accounts": [
    {"id":"ACC-DAILY","name":"Everyday","institution":"Example institution","type":"Transaction","owner":"Sam","openingMinor":"12345"}
  ],
  "budgets": [],
  "emergencyAccountId": null,
  "goal": null,
  "capacity": {"transactions":2000,"payslips":500,"valuations":500}
}
```

- Profile and Sheet version are required and exact. Country/currency may be omitted; when supplied they must be AU/AUD. All normalized output keys shown above are present.
- Names are trimmed and NFC-normalized. Household/account/institution/goal names have a 100 UTF-16-unit maximum; person names have an 80-unit maximum. Control characters are refused. One/two person names must be distinct ignoring case, without commas or the reserved `Joint`. People retain their supplied order.
- Supply 1–100 accounts. IDs match `[A-Z][A-Z0-9-]{0,39}`, are unique, and remain unchanged after setup. The generator never derives an ID from an editable name. Types are exactly `Transaction`, `Savings`, `Offset`, `Credit card`. Owners match a configured name or `Joint`. Accounts sort by ID in the normalized plan.
- `openingDate` is a real month-end in the supported 1900–2200 range, with a supported next import date. Every account uses that same statement-close anchor. The provider/UI should separately prevent a real setup date in the future. There is no clock-dependent default.
- Money is a canonical integer minor-unit **string**, not a decimal/float: `"12345"` is AUD123.45; `"-2900"` is AUD29 owing. Leading zeroes, `-0`, exponents and rounding are refused. Values and the total absolute opening balances are bounded to `99999999999999` minor units.
- Optional `budgets` entries are `{categoryId,monthlyMinor}` for existing expense categories. Budgets sort by category ID and cannot repeat. Omitted means unconfigured; explicit `"0"` means a zero spending limit. Annual combined budgets must fit the same exact range. The captured Monthly/Lumpy category treatment remains; lumpy bills use their annual budget for full-year comparisons.
- `emergencyAccountId` is null or a configured non-card account. No target months are assumed. Optional `goal` is `{name,targetMinor,targetDate,accountId}`: a positive target, date after the opening anchor and configured non-card account. No goal is generated by default.
- Omitted budgets/goal/emergency become `[]`/`null`/`null`. Capacities count records excluding headers, default to `2000/500/500`, and permit 1–100000 per raw table. Formats and validation extend with the requested capacities. Unknown fields, currencies, countries or domain options fail visibly.

## Output and provider boundary

The plan contains `profile`, `sourceSha256`, canonical `inputSha256`, `normalizedInput`, `reviewSummary`, `spreadsheetCreate`, `batchUpdate`, `verification` and `adaptations`.

`spreadsheetCreate` is a standard Sheets create body containing only spreadsheet properties. `batchUpdate` is a standard body containing all generated `addSheet`, typed `updateCells` and bounded `repeatCell` requests. It also works after the bootstrap service creates a blank Google Workspace spreadsheet through Drive. The 21 generated tabs use deterministic IDs 1000–1020; no provider default tab ID is assumed and no Drive file ID is invented.

The writer must establish a newly created owned/marked workbook, discover its initial tabs, verify them empty, and remove only those default tabs **after** the generated `addSheet` requests, within the same atomic batch. It must never apply this plan to an existing household. The batch is capped below 1.9 MB; typical output is approximately 325 KB. Interrupted creation requires durable status recovery, not an automatic second creation.

All user text is written as `stringValue`; even text beginning `=` is never treated as a formula. The known public feed is explicitly `no`. Permissions, protected ranges, existing Apps Script deployments and sharing are separate provider state.

`verification` exposes:

- `sheets`: expected `{sheetId,title,rowCount,columnCount}` and `ranges`: bounded A1 reads covering those grids.
- `cells`: the exact expected entered-cell map `{sheetId,rowIndex,columnIndex,userEnteredValue}`. Provider readback must also reject unexpected entered/formula cells.
- `formulaFingerprint`: SHA256 of canonical sorted `[title,rowIndex,columnIndex,formula]` tuples; `inputFingerprint`: SHA256 of canonical sorted `[title,rowIndex,columnIndex,userEnteredValue]` tuples for non-formulas. Sort is tab-title lexical order, then row and column. `expectedFingerprints` is exported for the exact implementation.
- `checks`: `{id,range,kind,expected?}`. `exact` compares a JSON cell matrix; `minor` compares finite monetary numeric cells after two-decimal conversion with canonical minor strings (`currency:"AUD"`); `blank` requires absent/empty effective values, never numeric zero. These cover opening balances/cash, dates, budget count, empty raw records, unsupported history and unavailable modules.
- `allowErrors:[]`: no unexpected effective spreadsheet errors are allowed. `rawRecordRanges` specifies the empty initial ledgers. Number formats and validation are encoded in the requests and should also be read back.

The initial As-of date is the opening anchor. Settings rows 35–37 add the immutable opening anchor, derived history start, and optional emergency-account role without shifting the existing positional settings. Only subsequent evidence-backed close advances As-of. The transaction-date validation and Close flags identify pre-anchor records. The authenticated importer also independently validates these profile settings and Accounts G, and rejects posted CSV rows on or before the anchor before source upload or a new write intent. Native preview uses the same service-derived dates. Legacy Sheets retain their prior import contract; no migration is performed. See the [writer boundary](../import-service/README.md).

## Deliberate scope

Accounts and tracked cash are supported immediately. Monthly cash flow needs the first closed month. Three-month/prior-year comparisons wait for complete windows. Full financial-year budgets remain unavailable when history starts after 1 July; current-month spending remains useful. Whole-household net worth, tax, mortgage, assets, subscriptions and savings-opportunity analysis remain unavailable, with no inherited numbers or active formula skeletons. Payslips can still be reviewed and matched to actual deposits through the existing importer; that does not enable tax forecasting.

The generator keeps raw headers and the ten original helper anchors unchanged, and initializes the writer's reserved Payslips I/Valuations F record-ID headers. A no-activity account is a Data diagnostic: the service's close still requires matching statement evidence for every relevant account. Zero formula Close flags is not proof of a verified close. See [ADAPTATION.md](ADAPTATION.md) for the source findings and deliberate changes.

Tests cover deterministic serialization, hostile/ambiguous input, exact cents and bounds, standard-request decoding, formula/input fingerprints, preserved raw contracts, optional-domain absence, history gates, zero budgets, account roles, expanded capacities and compatibility with a synthetic native readback. They **do not evaluate Google formulas**. Actual Google recalculation and complete initial readback now pass for one- and two-person fictional workbooks; see [provider evidence](evidence/GOOGLE-ACCEPTANCE.md). Hosted creation/recovery, native OAuth, first app import/replay and a second Google identity remain release acceptance work.

## Captured source

[davies-v1.json](source/davies-v1.json) was captured read-only from the [public fictional Davies workbook](https://docs.google.com/spreadsheets/d/1zfiCnqO36a0YmMwC8-J6iGHUGvmLdXmhbL5aPWNlExM/edit) on 5 November 2026 Sydney time. Its SHA-256 is `41743ff2a6bcbc21fc112656a4a3af71d9d2d233aa23657e801b3112ad4268ab`.

All 21 grids were read at their reported bounds. The manifest retains 3,193 populated source cells, including all 1,981 formulas, plus data validation and number formats. Repeated rules/formats are grouped into contiguous row ranges with one-based coordinates. Fictional raw values in Transactions A2:J, Payslips A2:G and Valuations A2:C were omitted; their headers, formula anchors, validation and formats remain. Fictional **configuration** still exists in the source and must be replaced by the generator.

The [capture comparison](source/capture-check.json) matched every fetched formula, 5,735 validation cells and 8,170 number-format cells, with no mismatches. It confirmed that 8,466 raw input values were omitted. This comparison did not calculate formulas or create a Sheet. Reads spanned multiple requests, so this is not an atomic snapshot. Visual styles other than number formats, merged cells, charts, protections, permissions and bound scripts are outside the capture.

The current private project's default branch contains raw-demo-data and HTML generators, but no complete Sheet builder was found there. This public formula capture makes recovering that original builder unnecessary for the next implementation. See [the required adaptations](ADAPTATION.md).

The pinned source and capture comparison are immutable inputs to this generator. Source integrity is checked on module load. A source or profile change requires explicit review and versioning; a captured formula is not automatically suitable for a blank household.
